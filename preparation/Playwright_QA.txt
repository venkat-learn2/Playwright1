9.What are the different locators strategies?
        > page.getByRole() to locate by explicit and implicit accessibility attributes.
        >page.getByText() to locate by text content.
        >page.getByLabel() to locate a form control by associated label's text.
        >page.getByPlaceholder() to locate an input by placeholder.
        >page.getByAltText() to locate an element, usually image, by its text alternative.
        >page.getByTitle() to locate an element by its title attribute.
        >page.getByTestId() 
        > Also use CSS and Xpath selectors
==================================================================================================        
10.what is recommeded locator strategy?

        > Role based locators
        > They align with accessibility standard
        > more resilient to UI Changes 
        > example - await page.getByRole('button',{'name:'Submit'}).click();

16. What is browser , context , page in playwright?
        
        >Browser = Apartment Building
        Context = Individual Flat
        Page = Room inside the flat

        > BROWSER - A browser instance that Playwright launches. - example: Chromium,Chrome,firefox
        > const browser = await chromium.launch();
        > One browser may have many contexts

        > BROWSER CONTEXT - A fresh isolated session inside the browser.
            > Each context has:    
                Separate cookies    
                Separate cache    
                Separate storage    
                Separate login session

            👉 Works like Incognito window.

        > const context = await browser.newContext();

        > Multiple users testing simultaneously

        > Parallel execution

        > No session conflict

        > - PAGE - A single browser tab where automation happens.

            > This is where you:

               > Click

               > Type    

               > Navigate

               > Assert
        const page = await context.newPage();
        await page.goto("https://example.com");       

        > Playwright uses browser contexts to provide test isolation without launching multiple browsers, which improves performance

31. API Testing Status Code 

        1. 2XX - success code 
                1. 200 - OK - Request Successful  - GET 
                2. 201 - Created - Resource Created - POST
                3. 202 - Accepted - Request Accepted , processing Later - 
                4. 204 - No Content - Succcess but no response - DELETE

        2.3XX - Redirection Code 
                1. 301 - permanet Redirect
                2. 302 - Temporary Redirect 
                3. 304 - Not Modified (cache issue)
        
        3. 4XX - Client Erros 
                1. 400 - Bad Request - Invalid Input - Missing Required field 
                2. 401 - Unauthorized - Auth Required - no token 
                3. 403 - Access denied - role restriction
                4. 404 - Not Found - Wrong Endpoint
                5. 405 - Wrong HTTP Method - POST instead of GET
                6. 409 - Conflict - Duplicate Data
                
        4. 5XX - Server Erros 
                1. 500 - Internal Server - Server crashed - code issue 
                2. 502 - Bad Gateway - Microservice error 
                3. 503 - Service Unavailable - Maintainance
                4. 504 - Gateway timeout - Slow backend
